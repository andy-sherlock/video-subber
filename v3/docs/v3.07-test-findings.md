# V3.07 端到端实测 — 技术审查报告

> **给审查工程师：** 本文档只描述项目背景、系统架构、测试数据和发现的问题根因。**不包含任何修复方案**，以免限制你的独立判断。

---

## 1. 项目背景

一个桌面端视频字幕自动生成工具（macOS Apple Silicon + Windows）。用户上传视频或粘贴 YouTube 链接 → 自动下载 → 语音转文字 → 多层幻觉过滤 → 翻译 → 字幕烧录。

### 1.1 完整流水线

```
下载 (yt-dlp) → 分轨提取 (ffmpeg)
       ↓
Whisper 转录 (faster-whisper large-v3, MLX GPU)
       ↓
三模型并行交叉验证：
  ├── Qwen3-ASR 1.7B（MLX 加速）→ 与 Whisper 文本比对 (L2)
  ├── Qwen3-ForcedAligner 0.6B（MPS）→ 词级时间戳对齐
  └── SenseVoice Small → 声音分类 (Speech/BGM/Music/Applause)
       ↓
五层幻觉过滤 (L1→L2→L4→L5→L3)
       ↓
LLM 上下文感知翻译 (DeepSeek/自定义) + 免费引擎兜底 (Google/Bing/有道)
       ↓
字幕烧录 (ffmpeg)
```

### 1.2 五层过滤架构

| 层 | 输入信号 | 判断内容 |
|----|---------|---------|
| L1 | SenseVoice + FA 对齐 | 这段是否有人声？（双信号交叉验证） |
| L2 | Whisper 文本 vs Qwen ASR 文本 | 转写文字是否可信？（窗口词干比对） |
| L3 | 语速 + 时长 | 是否符合正常说话节奏？ |
| L4 | 关键词过滤 | 是否有循环句式/重复词？ |
| L5 | 上下文连贯性 | 相邻段是否语义连贯？ |

**L1 判断矩阵（四象限）：**

| SenseVoice | FA 对齐 | L1 决定 |
|------------|---------|---------|
| 非人声 | 无对齐词 | 丢弃（双确认非人声） |
| 非人声 | 有对齐词 | 保留，推翻 SV 判定（SV 误判） |
| 人声 | 无对齐词 | 保留 + 标记 [?]（疑似幻觉） |
| 人声 | 有对齐词 | 正常通过 |

**L2 窗口比对：**

将连续段落分组为窗口，在每个窗口内计算 Whisper 和 Qwen ASR 的词干重叠率。阈值 0.35：
- GREEN：重叠率 ≥ 0.35（Qwen 确认 Whisper 的转写）
- YELLOW：重叠率 < 0.35（Qwen 未确认，存疑）
- NO_QWEN：窗口内无 Qwen 输出（无法交叉验证）

### 1.3 翻译架构

```
第一步：LLM 生成内容摘要 + 提取术语表
第二步：滑窗翻译（带重叠 + 接缝审查）
第三步：质量反思（reflection.py，LLM 审查修正自己的翻译）
       ↓
免费引擎兜底（Google/Bing/有道）补全 LLM 遗漏的段落
```

**当前状态：** 第三步（质量反思）代码已编写但未接入流程。

**滑窗分块机制：**
- 块大小 = (模型上下文窗口 - 18000) ÷ 8，钳位 [200, 3000]
- 块间 20% 重叠
- 接缝审查：多块时触发，比较重叠区两个版本的翻译，选优

**翻译解析：**
- 期望格式：`[编号] 翻译内容`
- 逐行正则匹配
- 中文比例校验：中文字符 ≥ 10% 才接受（不满 10% 视为未翻译，丢弃）

## 4. 发现的问题

### 问题 1：字幕时间戳漂移（约 1 秒偏差）

**现象：**
字幕有时提前约 1 秒出现（"人还没说话字幕先出来了"），偶尔延迟。大部分偏差为提前。观看时能明显察觉——话语和字幕不同步。

**发生位置：**
`apply_aligner_timestamps()` 函数。该函数负责将 FA 对齐器产生的词级时间戳分配回 Whisper 转录的 515 个段落。

**当前实现逻辑：**
程序将 FA 产出的 3078 个对齐词组织为一个扁平列表，按顺序分配给 515 个段落。分配方式为：读取每个段落的英文文本，用 Python 的 `str.split()` 统计单词数，从对齐词列表中消费对应数量的词。

```
段 N 的文本有 W 个单词（Python split 计数）
→ 取 aligned_words[word_idx : word_idx + W]
→ 用这 W 个词的首词 start 和末词 end 更新段 N 的时间范围
→ word_idx += W
→ 处理段 N+1
```

**根因：**
Python 的 `str.split()` 分词粒度与 FA 模型内部分词粒度不一致。例如 "we're" Python 计为 1 词，FA 模型可能将其拆分为 "we" + "'re" 计为 2 词。每个段落可能产生 1-2 个词的粒度偏差，515 个段落累积后，`word_idx` 指针漂移可达数十个词的位置。结果：段 N 的时间戳实际来自段 N-2 或 N-3 的对齐词，时间偏差约 1-2 秒。

---

### 问题 2：背景音乐段落的存疑率过高（54% [?]）

**现象：**
最终输出中 54% 的字幕被标记为存疑 [?]。但人工观看后发现，这些被标记的段落翻译质量大多是合格的。用户感受是"过度警告"——标记与实际质量不匹配。

**完整因果链：**

1. 测试视频全程有背景音乐（London Vlog）。SenseVoice 检测到 BGM 后将该段标为"非人声"。
2. FA 对齐器在同样的音频段中找到了完整的词级对齐结果——说明确实有人声。
3. L1 基于 FA 证据推翻了 SV 的 BGM 判定（"SV 误判清除"，触发 233 次），段落被正确保留。
4. 这些保留的段到达 L2。L2 用 Qwen ASR 的转写与 Whisper 比对。但 Qwen ASR 同样受背景音乐干扰——它在 BGM 环境中听不清，产出的转写质量下降。
5. 由于 Qwen 的转写与 Whisper 匹配度不足 0.35 的 GREEN 阈值，14 个窗口被标为 YELLOW，5 个窗口无 Qwen 输出被标为 NO_QWEN。
6. 这些窗口内的段落最终显示为 [?]。

**根因：**
L2 的 GREEN/YELLOW 判定阈值 0.35 对所有音频条件使用统一标准。背景音乐干扰下 Qwen ASR 的转写质量必然下降——这不是 Whisper 转写错误，而是 Qwen 自身受噪音影响无法有效交叉验证。L2 没有区分"Qwen 确认转写错误"和"Qwen 因音频条件限制无法确认"。已知存在 BGM 干扰的段落（L1 已标记为 SV 误判）仍用相同的 0.35 阈值判定。

---

### 问题 3：DeepSeek 翻译结果中 2 段未被解析（489/491）

**现象：**
DeepSeek 返回了 491 段的翻译结果，但程序只成功解析了 489 段。2 段被标记为"翻译失败"后由免费引擎（Google/Bing）补全翻译。日志未显示 DeepSeek 报错或返回空内容，表明 DeepSeek 确实返回了结果，但在解析环节被丢弃。

**发生位置：**
`_translate_one_chunk()` 函数中的翻译结果解析逻辑。

**当前解析流程：**
1. DeepSeek 返回一大段原始文本
2. 逐行匹配正则 `\[(\d+)\]\s*(.+)`（严格要求 `[数字] 空格 内容`）
3. 匹配成功后，提取编号和翻译内容
4. 校验翻译内容的中文字符比例（必须 ≥ 10%）
5. 任何一个条件不满足 → 丢弃该行

**可能原因（需进一步确认）：**

**A. 格式偏差：** DeepSeek 在生成 489 段正常格式后，可能在个别段落产生了微小的格式偏差（如 `[ 50]` 多空格、`【50】` 中文括号、`50.` 编号后无括号等），当前正则无法匹配。

**B. 中文比例校验过严：** 10% 的中文字符比例要求对于包含英文专有名词的短句（如 "Nando's 见"——5 字符中仅 1 个中文，比例 20% 勉强通过；若加上标点或更短的句子则可能低于 10%），可能将实际已翻译的短句误判为"未翻译"。

**C. 第三道防线未生效：** 项目中已编写了 `reflection.py`（质量反思模块），设计意图是在滑窗翻译完成后由 LLM 审查并修正自己的输出。但该模块从未被接入翻译流程（orchestrator 中无调用），因此无法在第二步之后进行补救。此外，reflection 模块使用了与第二步相同的严格正则匹配，即使接入也会因相同的格式问题漏掉同样的错误。
