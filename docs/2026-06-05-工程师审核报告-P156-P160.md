## 一、项目背景（供外部工程师了解上下文）

### 1.1 这个项目是什么

视频中文字幕生成工具。用户拖入任意语言视频，自动生成中文字幕。活跃代码在 `v2/` 目录。

### 1.2 转录流水线

```
视频 → 提取音频 → 转录 → 幻觉过滤 → 翻译 → 字幕输出
```

转录阶段有三个模型（用户可选三档）：

| 模型 | 角色 | 语言覆盖 |
|------|------|----------|
| **Whisper large-v3** | 主力转录。产出带时间戳的句子（254 段/24分钟视频） | 99 种 |
| **SenseVoice** | 声音分类。识别"人声/音乐/呼吸/掌声/笑声" | 不转录文字 |
| **Qwen3-ASR 1.7B** | 交叉验证转录。听同一段音频，产出独立转录文字 | 52 种 |

精确模式三个模型全部启用。标准模式只用 Whisper + SenseVoice。

### 1.3 千问的生成参数

```python
# v2/backend/core/qwen_asr_runner.py（第 49-56 行——当前生效代码）

_QWEN_REPETITION_PENALTY = 1.1    # 重复惩罚力度
_QWEN_REPETITION_WINDOW = 256     # 惩罚窗口（token 数）
_QWEN_TOKENS_PER_SEC = 20         # 每秒 token 预算。300秒×20 = 6000 token 上限
_QWEN_MIN_TOKENS = 256            # 兜底

def _qwen_gen_kwargs(duration_s, language=None, use_mlx=True):
    cap = max(_QWEN_MIN_TOKENS, int(duration_s * _QWEN_TOKENS_PER_SEC))
    # MLX → max_tokens=cap, PyTorch → max_new_tokens=cap
    kwargs["max_tokens" if use_mlx else "max_new_tokens"] = cap
    kwargs["repetition_penalty"] = _QWEN_REPETITION_PENALTY
    kwargs["repetition_context_size"] = _QWEN_REPETITION_WINDOW
    return kwargs
```

千问处理长音频时分段切块（chunk）。每个 chunk 最多 5 分钟（`_CHUNK_MAX_DURATION_S = 300`），在 Whisper 自然段落边界处切割。24 分钟视频 ≈ 5 个 chunk。**参数中的 `_QWEN_TOKENS_PER_SEC` 控制的是单个 chunk 的 budget，不是整部视频。**

### 1.4 幻觉过滤现有架构

```python
# v2/backend/core/hallucination_filter.py — 处理顺序
L1: SenseVoice + Qwen3-FA 双信号硬过滤（Phase 1D）
L4: 正则模式硬过滤（关键词/结构/括号描述）
L5: 连续重复去重
L2: 千问交叉验证软标记（← 本次核心改动）
L3: 语速异常软标记
```

过滤后的段经过 `worker.py` 检查点持久化（第 300-316 行），保存字段包括 `uncertain`、`sensevoice_tag`、`qwen_text`。

## 二、问题时间线

### 2.1 问题一：千问重复坍缩（P147）

**怎么发现的**：job `97c57255ec`，24分钟俄语视频，tier=precise。千问在音频前 2 分钟后陷入重复坍缩——从第 120 秒开始每段输出同一串垃圾 `1056234897 НЕТ ТЫ МЕНЯ ПРОСТИ`。chunk 5 卡了 13.5 分钟。最终 198 段中 116 段（58%）是这串垃圾。

**根因**：旧代码调用千问时**零参数传入**，全吃默认值：
- `max_tokens` 不传 → 自动 时长×50≈15000/chunk。坍缩后没有熔断，狂吐 15000 token 才停
- `repetition_penalty` 默认 1.2，太弱
- `repetition_context_size` 默认 100，窗口太小
- `language` 不传 → 每 chunk 独立重判语言

**修复（已执行）**：

```python
# P147 初版（三次修理历史——已废弃）
_QWEN_REPETITION_PENALTY = 1.4    # 1.2→1.4  ← 矫枉过正
_QWEN_REPETITION_WINDOW = 256     # 100→256
_QWEN_TOKENS_PER_SEC = 10         # 新增 50→10  ← 太紧

# P156 二次校准（当前生效代码）
_QWEN_REPETITION_PENALTY = 1.1    # 对齐 WhisperJAV 竞品
_QWEN_REPETITION_WINDOW = 256     # 保持不动
_QWEN_TOKENS_PER_SEC = 20         # 对齐 WhisperJAV
```

**教训**：P147 一次性改了三个参数，无法隔离哪个解决了坍缩、哪个造成了副作用。应该一次改一个，验证通过再改下一个。

**验证结果**：端到端测试 254/254 翻译成功。247 个单元测试全过。

### 2.2 问题二：千问"不说话"（P156）

**怎么发现的**：P147 修完后的第一次端到端测试（job `0a73f157b2`）。日志显示 `qwen=12 whisper=186`——千问 raw 转录只产出了 12 句。交叉验证映射率从 85% 跌到 6%。

**排查过程**（三步排除法）：

**步骤一**：排除对齐问题。`qwen=12` 是 raw 转录结果（`_split_sentences` 返回的完整句子数），不是对齐环节丢的。千问本身就没说话。

**步骤二**：排除语言问题。千问 3 对俄语 FLEURS WER=5.99（约 94% 正确率），30 种语言排第 13 名。不是"俄语太差"。

**步骤三**：对比赛品。WhisperJAV 的千问参数是 `repetition_penalty=1.1` + `max_tokens_per_second=20.0`。我们的 P147 是 1.4 + 10——在两个维度上比竞品极端 3-5 倍。

**根因**：
- **主犯** `repetition_penalty=1.4`：俄语是屈折语，同一个词根在 256 token 窗口内出现十几次。每出现一次罚一次→千问提前结束生成
- **从犯** `TOKENS_PER_SEC=10`：5 分钟 chunk 只给 3000 token 预算，刚好在边界
- **协同效应**：1.4 不让说话 + 10t/s 不给时间 = 93% 输出消失

**修复**：见 2.1 中的"当前生效代码"。`1.4→1.1`，`10→20`。

**验证结果**：端到端测试 job `1b520de51c`。千问产出 2062 句，坍缩 0%，翻译 254/254 成功。

### 2.3 问题三：千问和 Whisper 对不上（P160——本次核心问题）

**怎么发现的**：P156 修完后千问正常了（2062 句），但交叉验证映射率只有 35%（92/266）。20 分钟的千问推理，只产生了 **1 条**交叉验证信号。在 `qwen_asr_runner.py:90-115` 行发现了旧数据处理的根因。

**根因有三层**：

#### 根因一：逐字母比对看不懂俄语

```python
# 旧对齐逻辑（qwen_asr_runner.py 第 90-115 行）
def _match_qwen_to_whisper(qwen_sentences, whisper_segments):
    for qs in qwen_sentences:
        best_score = 0.0
        for i, st in enumerate(segment_texts):
            score = SequenceMatcher(None, qs_key, st).ratio()  # 逐字符比较
            if score > best_score:
                best_score = score
                best_idx = i
        if best_score > 0.2:  # ← 俄语变形后经常 <0.2
            pairs.append((qs, best_idx))
    return pairs
```

俄语同一个"钱"有六种写法（деньги/денег/деньгах/деньгам/деньгами），逐字母相似度只有 55-60%。真实测试数据：

```
Whisper: "Блин, по голове его постучало."
千问:   "Поговори, поговори, мы постучала"
→ 58% → 低于很多正确对子的门槛

Whisper: "Саш, привет. Я к тебе по делу."
千问:   "Ладно, я к тебе по делу"
→ 72% → 核心内容一模一样，只开头不同
```

#### 根因二：千问和 Whisper 说话节奏不同

千问 2062 句（短句），Whisper 254 段（长句）。按段号对齐天然错位——千问第 97 句可能对应 Whisper 第 12 段，但系统不知道。

#### 根因三：SenseVoice 一个人说了算

日志证据：24 分钟视频只识别了 5 个声音事件（3 个 Speech，2 个 Breath），凭这 5 个标签自动删除了 109 段（29% 的内容）。千问没有二次确认机制。

**解决方案（已实现）**：

架构从"逐段逐字母比对"改为"30秒窗口 + 词干提取 + 双重确认"：

#### 改动一：新增 LightweightStemmer 类

```python
# v2/backend/core/hallucination_filter.py（第 16-113 行——新增）

class LightweightStemmer:
    """零依赖多语言词干提取器（P160）
    
    桌面应用安全——无 NLTK、无模型下载、无网络请求
    每种语言配不同"裁刀"：
      zh — 逐字提取（汉字本身不变形）
      en — 手写裁 -ing/-ed/-es/-s/-tion/-ment/-ness/-ly + 双辅音终止
      ru — 手写 Snowball 式后缀表
      ja/ko — 滤语法助词，留实词
    """
    @staticmethod
    def clean_and_stem(text, lang):
        if not text or not text.strip():
            return set()
        text = text.lower()
        
        # 中文：提取单个汉字
        if lang == "zh":
            return set(re.findall(r'[一-龥]', text))
        
        # 英语：轻量词尾剥离
        if lang == "en":
            words = re.findall(r"[a-z0-9']+", text)
            stems = []
            for w in words:
                if len(w) >= 4:
                    if w.endswith('tion') or w.endswith('ment') or w.endswith('ness'):
                        w = w[:-4]
                    elif w.endswith('ing'):
                        w = w[:-3]
                        if len(w) >= 3 and w[-1] == w[-2]:
                            w = w[:-1]  # running→runn→run（双辅音终止）
                    elif w.endswith('ed') or w.endswith('er') or w.endswith('ly'):
                        w = w[:-2]
                    elif w.endswith('es'):
                        w = w[:-2]
                    elif w.endswith('s') and not w.endswith('ss'):
                        w = w[:-1]
                stems.append(w)
            return set(stems)
        
        # 俄语：手写 Snowball 式后缀剥离
        if lang == "ru":
            words = re.findall(r'[а-яё0-9]+', text)
            stems = []
            ru_suffixes = (
                'его', 'ого', 'ами', 'ями', 'ов', 'ев', 'ей', 'ег',
                'ах', 'ях', 'ом', 'ем', 'ой', 'ую', 'юю', 'ая', 'яя',
                'ое', 'ее', 'ые', 'ие', 'ым', 'им', 'их', 'ых',
                'ешь', 'ет', 'ем', 'ете', 'ут', 'ют',
                'ишь', 'ит', 'им', 'ите', 'ат', 'ят',
                'ся', 'сь', 'л', 'ла', 'ло', 'ли',
                'ть', 'ти', 'а', 'я', 'о', 'е', 'ы', 'и', 'ь',
            )
            for w in words:
                if len(w) > 3:
                    # 第一轮：长后缀
                    for suff in ru_suffixes:
                        if w.endswith(suff):
                            w = w[:-len(suff)]
                            break
                    # 第二轮：短后缀兜底
                    for suff in ('а', 'я', 'о', 'е', 'ы', 'и', 'ь'):
                        if w.endswith(suff) and len(w) - len(suff) >= 3:
                            w = w[:-len(suff)]
                            break
                    # 第三轮：再剥离尾随软音号
                    if w.endswith('ь') and len(w) > 3:
                        w = w[:-1]
                stems.append(w)
            return set(stems)
        
        # 日语/韩语：滤语法助词
        if lang in ("ja", "ko"):
            words = re.findall(r'[぀-ゟ゠-ヿ一-龯가-힣]+', text)
            if lang == "ja":
                ja_particles = {'は', 'が', 'を', 'に', 'の', 'で', 'へ', 'と',
                                'から', 'まで', 'です', 'ます', 'た'}
                return {w for w in words if w not in ja_particles}
            return set(words)
        
        # 兜底：按空格分词
        return set(text.split())
```

#### 改动二：重写 _layer2_cross_validate

```python
# v2/backend/core/hallucination_filter.py（第 295-389 行——替换旧版）

def _layer2_cross_validate(segments: list, language: str = "auto",
                           custom_thresholds: dict = None):
    """P160: 30秒窗口 + 词干重叠 交叉验证（B+A 架构）

    替代旧的逐段 SequenceMatcher 做法。两趟流程：
      1. 双重确认——SenseVoice + qwen_text：两个都同意的非人声段自动标记
      2. 窗口化——把音频切成30秒窗口，裁词尾，比对词干组。
         超过门槛 → GREEN，低于 → YELLOW

    返回 (annotated_segments, window_stats)
    """
    if not segments:
        return segments, {}

    # —— 按语言定门槛 ——
    thresholds = {
        "zh": 0.55, "en": 0.35, "ru": 0.28,
        "ja": 0.45, "ko": 0.45,
    }
    if custom_thresholds:
        thresholds.update(custom_thresholds)
    current_threshold = thresholds.get(language, 0.30)

    # —— 第一趟：双重确认 ——
    for seg in segments:
        sv_tag = getattr(seg, "sensevoice_tag", None)
        qwen_text = (getattr(seg, "qwen_text", None) or "").strip()

        if sv_tag and sv_tag != "Speech" and not qwen_text:
            # 两人一致：非人声 + 千问也没说话 → 幻觉
            seg.filtered = True
            seg.filter_reason = "layer2_sensevoice_qwen_agree"
        elif sv_tag and sv_tag != "Speech" and qwen_text:
            # 两人矛盾：SV 说非人声但千问听到了话 → 可疑
            seg.uncertain = True

    # —— 第二趟：窗口化 + 裁词尾 ——
    WINDOW_SIZE = 30
    total_duration_s = max(getattr(s, "end", 0) for s in segments)
    if total_duration_s <= 0:
        return segments, {}
    num_windows = int(total_duration_s // WINDOW_SIZE) + 1

    whisper_windows = ["" for _ in range(num_windows)]
    qwen_windows = ["" for _ in range(num_windows)]

    def _find_best_window(start, end):
        """最大重叠算法——替代旧版'时间中点'做法"""
        best = int(start // WINDOW_SIZE)
        max_overlap = 0
        for w in range(int(start // WINDOW_SIZE),
                       min(int(end // WINDOW_SIZE) + 1, num_windows)):
            ws = w * WINDOW_SIZE
            we = ws + WINDOW_SIZE
            overlap = min(end, we) - max(start, ws)
            if overlap > max_overlap:
                max_overlap = overlap
                best = w
        return best

    for seg in segments:
        if seg.filtered:
            continue
        win = _find_best_window(seg.start, seg.end)
        if win < num_windows:
            whisper_windows[win] += " " + seg.text
            qwen_windows[win] += " " + (getattr(seg, "qwen_text", None) or "")

    # —— 按窗口裁词尾 + 打分 ——
    window_stats = {}
    for idx in range(num_windows):
        w_text = whisper_windows[idx].strip()
        q_text = qwen_windows[idx].strip()

        if not w_text and not q_text:
            window_stats[idx] = {"status": "EMPTY", "score": 1.0}
            continue
        if not q_text:
            window_stats[idx] = {"status": "NO_QWEN", "score": 1.0}
            continue

        w_stems = LightweightStemmer.clean_and_stem(w_text, language)
        q_stems = LightweightStemmer.clean_and_stem(q_text, language)

        shared = w_stems & q_stems
        score = len(shared) / len(w_stems) if w_stems else 0.0

        if score >= current_threshold:
            window_stats[idx] = {"status": "GREEN", "score": score}
        else:
            window_stats[idx] = {"status": "YELLOW", "score": score}

    # —— 把结果打回到对应段上 ——
    for seg in segments:
        if seg.filtered:
            continue
        win = _find_best_window(seg.start, seg.end)
        ws = window_stats.get(win)
        if ws and ws["status"] == "YELLOW":
            seg.uncertain = True

    _log.info("L2 窗口比对完成: %d 窗口, 阈值=%.2f, %s",
              num_windows, current_threshold,
              {s: sum(1 for v in window_stats.values() if v["status"] == s)
               for s in ("GREEN", "YELLOW", "EMPTY", "NO_QWEN")})

    return segments, window_stats
```

### 2.4 问题四：平台专用架构问题的发现与修正

在实施方案构建期间，项目的 AI 审查系统（Steve Jobs Skill 及 plan-eng-review）发现了最终代码方案中存在以下 7 处必须排除的工程隐患：

**发现一：新 L2 必须从逐段处理改成批量处理**

旧代码在一个 `for seg in surviving` 循环里每次调 L2。新 L2 需要一次性收到全部段才能切窗口做时间对齐。`filter_hallucinations()` 的 L2 调用点必须从循环改为批量调用。改动 3 行。外部工程师在第二版代码中已修复此结构。

**发现二：SenseVoice 双重确认逻辑放在了 L2 而不是 L1**

新代码把 SenseVoice + 千问双重确认写在了 L2 函数里，但现有的 L1（`_layer1_dual_signal`）已经在做 SenseVoice + Qwen3-FA 的双重确认。两套防线对同一段音频用不同标准重复判断会在后续维护时产生误解。目前先放在 L2，合并到 L1 记录为后续优化项。

**发现三：英/俄词尾表存在已知缺口**

手写词尾列表遗漏了：`-ся`/`-сь`（俄语反身后缀，如 `заниматься`）、`-его`/`-ого`（形容词属格，如 `красного`）、英语缺少 `-tion`/`-ment`/`-ness`/`-ly` 及 `running→run` 的双辅音终止处理。**→ 已在前述代码中全部修复。**

**发现四：checkpoint 不保存新的过滤字段**

`worker.py:300-316` 读写 `uncertain`/`sensevoice_tag`/`qwen_text`，但不包含任何窗口级状态。如果用户关闭页面后重新打开，之前的窗口比对结果可能丢失。`seg.uncertain` 目前仍然在工作所以不紧急，但未来如果引入新字段就会暴露。记录为后续待办。

**发现五：进度显示粒度过粗（P159）**
