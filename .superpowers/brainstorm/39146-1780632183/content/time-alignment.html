你提出的"先翻译再对比再翻译"确实太绕了。但还有第三条路。

"先翻译再对比再翻译"是绕路
俄语音频 → Whisper转俄文 → 翻译成中文 → 对比 → 找错 → 再翻译一次 → 出字幕

翻译两次，LLM 调两次。又贵又慢。而且翻译本身也可能出错——你用可能有错的翻译去验证可能有错的转录，绕了一圈还是不确定。

第三条路：按时间对齐，不按文字对齐

你的项目里已经有了 Qwen3-ForcedAligner。它能给千问的每一个词打上精确的时间戳——这个词是第几秒到第几秒说的。

Whisper 也有时间戳——每一段从第几秒开始，到第几秒结束。

时间对齐 vs 文字对齐
现在的做法：文字对齐
Whisper 第1句: "Саш, привет..."
千问 第1句: "Ладно, я к тебе..."
↓ 比文字长得像不像
"Саш" ≠ "Ладно" → 不像 → 扔掉
改成：时间对齐
第 5.2 秒 ~ 第 8.3 秒
Whisper 说的是: "Я к тебе по делу"
千问 说的是: "я к тебе по делу"
↓ 同一个时间点，说的是不是同一件事？ ✓ "Я к тебе по делу" = "я к тебе по делу"

同一个时刻，两个人听到的是同一句话。不需要比字形。比的是：在这一刻，两个人写的东西是不是一样的。

时间对齐有什么好处？
  1. 不需要翻译。 不需要懂俄语。不需要 LLM。
  2. 不对抗俄语词尾。 文字怎么变都没关系。同一个时间点说的事，大概率是同一件事。
  3. 不丢千问的产出。 2062 句全部参与比对，不会因为"字不像"被扔掉 95%。
  4. 直接发现真幻觉。 如果第 120 秒 Whisper 写了一长串俄语句子，千问什么都没写——那 Whisper 在安静的时候编了东西。这才是真正的幻觉信号。
成本：你已经有这个工具了

Qwen3-ForcedAligner 已经在你的 Phase 1D 里集成了。每个词都有 start_time 和 end_time。只是现在只用在"给字幕分时间"这个步骤上。

把同一份对齐结果也拿给交叉验证用——零额外成本。

但也有限制

Whisper 的时间戳是句级的（这一段从第 5 秒到第 8 秒）。千问的词级时间戳更精确。对齐的精度取决于 Qwen3-FA 在 Mac MLX 上跑出来的时间戳质量。

并且——当你按时间对齐后，仍然需要判断"同一个时间点的两段文字意思是不是一样的"。只是这次你不是数字母了——时间帮你解决了"哪句对哪句"的问题。剩下的"这两句说的是不是同一件事"，可以用一个更简单的指标：两个句子共有的词所占的比例。
