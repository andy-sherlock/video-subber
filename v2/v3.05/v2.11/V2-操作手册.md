## 一、部署前准备：创建 GitHub 远程配置仓库

整套远程配置系统依赖一个 GitHub 私有仓库。**这是部署前必须做的第一件事。**

### 待办 1：创建私有仓库

1. 登录 GitHub → New repository → **Private**（必须是私有）
2. 仓库名建议：`video-subber-config`
3. 创建后在仓库里建三个 JSON 文件（见下方）

### 待办 2：创建 `activation_codes.json`

```json
{
  "codes": [
    "VSUB-DEV-第一个开发者的码",
    "VSUB-DEV-第二个开发者的码"
  ],
  "updated_at": "2026-05-22T12:00:00Z"
}
```

每个要使用开发者模式的人，在这里放一个码。码的格式随意，建议 `VSUB-DEV-` 开头方便辨认。

### 待办 3：创建 `models.json`

```json
{
  "models": []
}
```

空数组即可——应用会使用内置的默认模型列表。将来需要远程更新某个平台的模型时再加。

### 待办 4：创建 `platform_keys.json`

```json
{
  "keys": [
    {"platform": "glm", "name": "GLM 4.7 Flash（平台提供）", "key": "去智谱开放平台申请的真实 Key 填在这里"}
  ]
}
```

**这是 ¥3 付费档的核心**。应用启动时自动拉取这个文件，把 Key 缓存到内存。付费用户的翻译请求自动使用这些 Key。

格式：一个平台一条。`platform` 必须和代码里 `LLM_BACKEND_LIST` 的 `id` 一致（当前支持：claude / gpt / gemini / deepseek / doubao / glm）。

### 待办 5：修改代码里的仓库地址

**文件**：`v2/backend/main.py`，找到 `_REMOTE_BASE`（约第 107 行），把 `YOUR_USERNAME` 和 `video-subber-config` 改成你真实的 GitHub 用户名和仓库名：

```python
_REMOTE_BASE = _os.environ.get(
    "VSUB_REMOTE_CONFIG_URL",
    "https://raw.githubusercontent.com/你的GitHub用户名/你的仓库名/main",
)
```

改完这一行，三个 JSON 文件的远程拉取就全部接通了。

## 二、日常运维：怎么更新远程配置

所有远程 JSON 文件都在 GitHub 上。**改完即生效，不需要重新打包应用。** 应用每次启动时会拉取（激活码缓存 24h，模型列表缓存 24h，平台 Key 缓存 72h）。

### 加一个新的激活码

编辑 `activation_codes.json`，在 `"codes"` 数组里加一行 → 提交。下一个开发者 24h 内就能用。

### 撤销一个激活码

从 `activation_codes.json` 的 `"codes"` 数组里删掉那一行 → 提交。**已绑定的机器不受影响**（它们靠本地的 `activation.json` 保持激活），但该码无法再用于新机器。

### 换一个新的平台 Key

编辑 `platform_keys.json`，把 `"key"` 字段的值换成新的 → 提交。已启动的应用在下次拉取（72h 内）自动切换。

### 换一个新的 LLM 模型

编辑 `models.json` → 提交。下一个启动周期生效。

## 三、开发者模式：怎么让开发者激活

### 流程

1. 你在 `activation_codes.json` 里加一个码
2. 通过 Slack/微信私下把码告诉那个开发者
3. 开发者在应用右下角点 `?` → 输入码 → 点激活
4. 应用联网验证（从 GitHub 拉到最新的 `activation_codes.json`，确认码在其中）
5. 验证通过 → 绑定这台电脑的机器指纹 → 写入 `~/.video-subber/activation.json`
6. 以后这台电脑打开应用就是开发者模式——**离线也能用**

### 本地自测（不经过 GitHub）

如果你自己在开发调试，不想走 GitHub 远程拉取，设环境变量：

```bash
export VSUB_DEV_CODES="MY-TEST-CODE-1,MY-TEST-CODE-2"
```

应用启动后输入这些码就能激活。不会去拉远程。

### 付费 tier 自测

开发者模式激活后，URL 加 `?tier=paid_3` 即可模拟付费用户。平台 Key 从哪来：
- 如果设了 `VSUB_PLATFORM_KEYS` 环境变量 → 用环境变量的值
- 如果 GitHub 上有 `platform_keys.json` → 自动拉取
- 两者都没有 → paid_3 用户无平台 Key，翻译降级到免费后端

## 四、版本迭代：怎么做下一个版本

```
v2/                      ← 当前工作台（所有修改在这里做）
  backend/
  frontend/
  v2.05/                 ← 上一版本快照（只读，不删不改）
  v2.06/                 ← 下一版本快照（从这里复制开始）
```

### 操作步骤

1. 在 `v2/` 里改代码、测试
2. 全部验证通过后 → 把 `v2/` 全部文件复制到 `v2/v2.06/`
3. 旧版本 `v2.05/` 只读保留，效果不好随时换回去
4. 更新 `video-subtitle.md` 的版本表格

## 五、打包发布

### Windows

用 **auto-py-to-exe**：

```
pip install auto-py-to-exe
auto-py-to-exe
```

| 设置项 | 填什么 |
|--------|--------|
| Script Location | 选 `v2/desktop.py` |
| One File | ✅ 勾选 |
| Window Based | ✅ 勾选 |
| Additional Files → 添加 | `v2/frontend/index.html` → 目标填 `frontend/` |
| Additional Files → 添加 | `v1/v1.3/video_subber/` → 目标填 `v1.3/video_subber/` |

→ 点 **Convert .py to .exe**。

### Mac

```bash
pyinstaller --onefile --windowed \
  --add-data "frontend/index.html:frontend/" \
  --add-data "../v1/v1.3/video_subber:v1.3/video_subber/" \
  desktop.py
```

打包成 DMG：
```bash
hdiutil create -volname "Video Subber" \
  -srcfolder dist/ \
  -ov video-subber-v2.0.dmg
```

### 注意

打包出的成品**不含** ffmpeg 和 Whisper 模型。用户首次使用时应用会自动检测并引导安装/下载。

## 七B、V2.08 已实现但未完成的功能

### "存回原位"功能（Plan A）— 第 3 步尚未实现

**背景**：用户希望输出文件保存在原视频所在文件夹，而非固定的 `~/Downloads/Video-Subber/`。

**已完成（2026-05-24）**：
- `main.py`：处理 `local_path` 时，自动将 `source_dir = Path(local_path).parent` 写入 job config
- `worker.py`：输出时优先读取 `config["source_dir"]`，存在且合法则存回原位，否则降级到 `savePath`
- 浏览器模式不受影响（无 `local_path` → 无 `source_dir` → 走原有逻辑）

**未完成（待 EXE 打包阶段实现）**：

**任务**：修改 `desktop.py`，拦截操作系统级文件拖拽，获取完整路径，以 `local_path` 参数发给后端。

**文件**：`v2/desktop.py`

**实现思路**：
- EXE 启动时，应用是一个本地浏览器窗口（WebView / 内嵌 Chromium）
- 需要在 WebView 层拦截 `dragover` + `drop` 事件，用原生 API 获取文件的**完整磁盘路径**（浏览器 File API 出于安全不暴露路径）
- 获取到路径后，以 JSON `{"local_path": "C:\\Videos\\trump.mp4", "config": {...}}` POST 到 `http://127.0.0.1:8766/api/jobs`，而不是上传文件内容
- 推荐方案：使用 `pywebview`（已支持 `window.pywebview.api` 调用 Python 函数），在 Python 侧通过 `webview.windows[0].get_elements()` 或 JS bridge 获取拖拽文件路径

**前置条件**：
1. 验证 `pywebview` 与当前 `desktop.py` + `uvicorn` 架构兼容
2. 或改用 `tkinter` / `wx` 做原生窗口壳，内嵌浏览器显示 index.html，同时暴露拖拽 API

**后端侧已就绪**，只差 `desktop.py` 这一步。

## 九、付费转化路径设计（待上线时实施）

> 来源：2026-05-24 乔布斯视角审查建议

**核心原则**：让用户先感受到痛点，再提供付费解决方案（而非在入口处展示灰色功能）。

**实施方案**：
1. 免费用户跑完翻译 → 结果中有 `[?]` 标记的不确定段落
2. 在 `[?]` 段落旁显示小字提示：「用 LLM 智能翻译消除不确定段落 → 了解更多」
3. 点击后展示付费方案（paid_1: 自备Key / paid_3: 平台提供）
4. 用户在**体验到免费版的局限之后**自然产生付费动机

**不要做的事**：
- 不要在首页展示灰色/禁用的付费功能入口
- 不要用"即将上线"的文字（暗示功能不存在）
- 不要在用户还没体验过产品时就推销付费
