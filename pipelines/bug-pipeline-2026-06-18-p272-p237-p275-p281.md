### plan-eng-review 结论（工程审查）
方案可以进入影响面分析，但要锁住 5 个边界：

1. **P272 接缝审查污染：用输出防线，不做第二次 LLM 修复。**
   这类问题的根因不是翻译质量差，而是 LLM 把“解释文字”混进了“字幕结果”。正确修法是在 `_review_seam()` 的解析出口挡住解释文字。只要一行像审查意见，就不允许写回正式字幕。有效行太少时返回 `None`，保留原译文。这比再问一次 LLM 更稳，因为第二次 LLM 仍可能继续解释。

2. **P237 黑匣子日志：只补异常快照调用，不扩展日志系统。**
   现在已有 `_crash_snapshot()`，缺的是异常退出时把快照写进 debug log。修复范围必须小：异常路径调用快照、快照失败不能覆盖原始异常、日志保持机器可读。不要在这一步重写日志结构。

3. **P281 Phase 2 字幕重组：人声地图只能帮忙判断“能不能合并”，不能直接删除字幕。**
   人声地图的作用是告诉我们“这一段像有人声还是不像有人声”。在同一人声区里的短词，可以把 `max_gap` 放宽一点去合并；落在非人声区的短词，先标 `uncertain/filter_reason`，不要直接删。原因很简单：SenseVoice 也可能误判，直接删会丢真字幕。

4. **P275 Phase 2 质量判断：只做可复核统计，不接 LLM。**
   这里的“质量判断”不是让大模型评价翻译好不好，而是在 ASR 结果出来后做体检：哪些人声区没有字幕、哪些非人声区出现短词、最长疑似漏字幕区在哪里。输出日志即可，先让测试可见，不要在这一轮做自动删改。

5. **P277 环境固定：V3.07 只固定运行方式，不搬家。**
   真实测试统一从 `v2/.venv/bin/python` 启动 server，worker 继承同一个 Python。长视频测试禁用 `--reload`。旧虚拟环境、历史目录、`v2/v2/` 等整理留到 V3.08，避免把“修字幕问题”和“搬目录”混在一起。
