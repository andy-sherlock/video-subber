### 结论（下一步只看这里）
安全审查发现 2 个需要当场修的小问题，均已在 HARDEN 阶段用失败测试锁住并修复：

1. 视频 URL 模式没有复用 `_verify_safe_url()`。
   - 风险：用户提交 `http://127.0.0.1:8766/...` 或 `http://192.168.1.1/...` 时，后端会让 `yt-dlp` 去访问本机或内网地址。
   - 修复：`_prepare_url_job()` 和 `/api/download-video` 都改为先调用 `_verify_safe_url()`。
   - 验证：`test/test_p188_url_validation.py` 新增 loopback、private network、standalone download endpoint 三个用例，先失败后通过。

2. `_validate_job_path()` 用字符串 `startswith` 判断目录归属。
   - 风险：同名前缀 sibling 目录，例如 `../jobs_evil`，可能绕过字符串前缀判断。
   - 修复：改用 `Path.relative_to()` 判断解析后的路径是否真的在 `JOBS_DIR` 下。
   - 验证：`test/test_harden_v307_sprint2.py::TestP240PathTraversal` 新增同名前缀 sibling 用例，先失败后通过。

其他检查结果：
- 子进程调用没有发现 `shell=True`，主要命令通过列表参数传递，命令注入面没有扩大。
- `worker_manager` 写 worker config 时会把配置写进 job 目录；这是既有行为，不是 V3.08 新增。
- 日志使用 `scrub_logs()` 脱敏常见 API key 样式，崩溃快照不包含 `apiKeys`。
- `config_manager` 明文保存 `apiKeys` 是当前测试明确锁定的既有产品选择：`test_plaintext_keys.py` 要求 key 明文保存以避免机器身份变化后读不回来。这是安全债，但不是 V3.08 拆分/搬家引入的回归，不阻塞本轮发布判断。
