### bill-gates 系统风险结论
系统层面最大的风险不是代码行数，而是一致性。

1. **健康判断必须只有一个来源**  
   如果 `_check_whisper_health()` 和 `_whisper_is_usable()` 并存，系统会出现两个标准。组装认为 Whisper 可用，Refiner 认为不可用，或者反过来。这会制造新的隐性状态分裂。

2. **`uncertain` 是跨阶段信号，不能随手清**  
   `uncertain` 从 L1/L2/L3/L4 进入 Refiner，再影响最终字幕问号。single 模式清错一次，用户看到的就是“系统明明没确认却装作确认”。所以 P269 的核心不是 prompt，而是状态转移。

3. **P268 是管道控制点**  
   SenseVoice 和 L1 的输入源决定后续数据质量。这里如果只改一半，比如 SenseVoice 看 Qwen，但搬运仍看 Whisper，系统会呈现“看起来修了，实际仍被 Whisper 拖住”的假修复。

4. **不要把 L4 做成分类系统**  
   L4 只能做模式处理：垃圾删，CJK 重复保留为不确定。真正的语义价值判断放后续版本，不进入本轮。

### 设计图（箭头写清楚数据格式）

1. Qwen ASR 原始输出 `qwen_chunks`  
   → `_qwen_chunks_to_segments()`  
   → Qwen L1 段列表：`Segment(text,start,end,id)`

2. SenseVoice 输出 `sv_events`  
   → `_apply_sv_tags(_qwen_l1_segments, sv_events)`  
   → 在 Qwen L1 段上写入 `sensevoice_tag`

3. Qwen 词级时间戳 `qwen_chunks.segments`  
   → `_qwen_segments_as_alignment()`  
   → L1 可读的对齐词列表：`[{text,start,end}]`

4. Qwen L1 段 + Qwen 对齐词  
   → `_layer1_dual_signal()`  
   → 在 Qwen L1 段上写入 `filtered / uncertain / bgm_override`

5. Qwen 原始词级时间戳  
   → `_smart_assemble()`  
   → 用户最终看到的字幕段：`_assembled`

6. Qwen L1 段上的 L1 标记  
   → `_propagate_l1_marks(_qwen_l1_segments, _assembled)`  
   → 把 `filtered / uncertain / bgm_override` 搬到最终字幕段

7. 最终字幕段  
   → `filter_hallucinations(..., skip_l1=True)`  
   → 只跑 L2/L3/L4/L5，不重复跑 L1

8. 带 `uncertain` 的字幕段  
   → Refiner dual/single  
   → dual 模式可以清未修正问号；single 模式只能清实际修正过的问号

### 审查范围

本轮不改登录、权限、上传接口、下载接口、系统命令、数据库、密钥存储。安全风险主要集中在 LLM 外发文本和日志。

### 结论

没有发现阻塞实现的安全问题。允许进入 ⑦ TDD。

需要写进实现约束的安全要求：

1. **Refiner single 模式只能发候选段**  
   候选段指 `uncertain=True`、明显短碎、或明显没结尾的段。不能在 single 模式下把整份转录全文都发给 LLM。

2. **不打印完整 prompt、不打印完整字幕文本**  
   当前日志只打印错误、段号、编辑距离和少量片段。本轮新增日志也只能记录数量、模式、段号，不记录完整成人内容。

3. **不要执行字幕文本里的任何指令**  
   字幕内容只是待校对文本。即使文本里出现“忽略上面的规则”之类内容，也只能当作普通字幕，不影响 system prompt。

4. **不新增外部网络入口**  
   本轮只复用已有 `_build_llm_backends()` 和 `translate_raw_json()`。不新增新服务、新 URL、新下载逻辑。

5. **不新增静默兜底**  
   Whisper 不健康时只能降级为 single 模式并记录日志，不能伪造 Whisper 参考稿，也不能伪造时间戳。
